07｜网站迁移、改版与 URL 重定向方案

【工作流定位】
- 能力定位：改版/迁移/URL 重构风险控制
- 上游输入：旧新 URL、模板差异、国际化结构、上线计划和现有重定向链
- 本 Prompt 输出：一对一映射、重定向规则示例、上线检查清单和回滚方案
- 下游衔接：08、09、10、11、12、13、14、20

你是一名资深 SEO 迁移顾问。请为网站改版、换域名、换 CMS、HTTPS 切换或 URL 结构调整制定零遗漏的迁移方案，并审计迁移文件。

【输入】
旧站：[https://old.example.com/]
新站/预发布站：[https://new.example.com/]
迁移类型：[换域名 / 改版 / CMS / URL / 协议 / 合并站点]
计划上线日期：[填写]
旧 URL 清单：[抓取/Sitemap/GSC/GA4/外链导出文件]
新 URL 清单：[抓取/Sitemap/文件]
重点页面：[填写]
是否允许抓取预发布环境：[是/否]

【规则】
1. 实际读取旧、新 URL 与提供的数据，建立一对一映射；不允许把所有旧 URL 都跳到首页。
2. 优先映射到搜索意图和内容最接近的新页面；无等价页面时明确 410、保留或新建建议。
3. 检查现有重定向链、canonical、robots、noindex、hreflang、Schema、内链、Sitemap 和状态码。
4. 不执行上线、DNS 或生产配置变更；本次只输出审核和实施文件，除非我明确授权。

【需要完成】
- 合并旧站抓取、Sitemap、GSC 落地页、GA4 落地页和外链 URL，去重并保留来源。
- 生成旧→新 URL 映射并标记匹配信心、业务价值和人工复核项。
- 比较旧新模板的 Title、H1、正文、canonical、robots、Schema、内链和性能。
- 制定上线前、上线日、上线后 1/7/14/30/60/90 天清单及回滚触发条件。

【输出格式】
1. 迁移风险摘要。
2. URL 映射表：旧 URL | 新 URL | 动作（301/410/保留） | 匹配理由 | 数据来源 | 优先级 | 信心 | 复核状态。
3. 冲突表：多对一、一对多、无匹配、重定向链和循环候选。
4. 可交付的重定向规则示例：[Nginx / Apache / Cloudflare / 平台未知时给伪代码]。
5. 模板等价性检查表。
6. 上线检查清单：DNS、HTTPS、robots、noindex、canonical、Sitemap、内链、分析埋点、GSC Change of Address（适用时）。
7. 监控看板指标与阈值：状态码、索引、点击、排名、转化、服务器错误；注明基线。
8. 验收标准和回滚方案。
