# Momcozy GEO 试点：最小验收单元与证据讨论稿

> **状态：L0 讨论基线（方法），2026-11-08。** 用户同意方案 A：先定义最小可验收单元与证据，不排日期、不承诺里程碑、不分配人员。本稿不是验收结果，也不代表任何能力已实现或通过。

## 1. 原则

1. **每项能力至少包含正例与负例。** 只有正例时，“永远拒绝”也可能通过验收；负例必须同时覆盖“该拒绝时拒绝”和“该通过时通过”。
2. **未执行不等于失败，也不等于通过。** 跳过、阻塞、缺环境须单独记录，不得计入通过数。
3. **证据必须可回看。** 结论指向具体记录、版本与位置；截图需带上下文，模型自评和口头确认不能替代人工验收。
4. **验收人与执行人分离。** 执行人自测只算自检；业务 UAT、合规声明和事实判断分别由对应 owner 确认。
5. **证据分级，不跨级声明。** 纸面、合成、隔离环境与真实业务验收各自只能证明其范围内的事。
6. **部分完成是合法结果。** 允许“部分通过 + 明确 HOLD”，但不得汇总成一个未被支持的“整体通过”。

## 2. 证据等级与可证明范围

| 级别 | 形式 | 能证明 | 不能证明 |
|---|---|---|---|
| L0 | 讨论稿、纸面评审 | 口径、边界与责任是否一致 | 任何实现、权限或数据行为 |
| L1 | 本地运行 smoke | 本机流程可运行 | 环境配置、权限、真实数据 |
| L2 | fixture / dry-run | 状态机与规则在合成数据下的行为 | 真实样本、真实权限、生产可靠性 |
| L3 | 经授权的只读或隔离环境（测试租户内的建连、收事件等有限实时行为单列 L3+，不当作纯只读） | 受控环境中的连通性、权限拒绝与失败处理 | 生产容量、真实业务效果 |
| L4 | 明确授权的实时动作 | 该次动作已完成且可审计 | 业务价值、因果关系、平台总体 |
| 生产验收 | 业务 UAT、签收、恢复演练 | 在约定范围内可交付 | 未覆盖范围与未来表现 |

合成数据验证通过只说明该测试场景，不代表真实权限配置或数据权利已就绪。

## 3. 六项能力的最小验收单元

| 能力 | 最小正例 | 最小负例 | 需留证据 |
|---|---|---|---|
| 1. 配置与问句库 | 创建 → 审阅 → 冻结 → 新版本可追溯 | 冻结后原位修改被拒；未审问题不能成为基线 | 版本记录、审批记录 |
| 2. 采集探针 | 计划项状态守恒，有效/失败/未执行可区分 | 未授权入口被拒；失败不得冒称成功；重试不替换有效结果 | 状态表、原始记录、权限日志 |
| 3. 解析与指标 | 每个数字可钻取至快照与规则版本；分母守恒 | 无把握输出 unknown；分母为零显示 N/A；纠错保留原版本 | 重算记录、钻取链 |
| 4. 诊断洞察 | 观察、事实、假设、建议分栏；候选待审 | 无证据不得断言根因；候选确认不触发派单或通知 | 诊断卡、审阅记录 |
| 5. 内容生成 | 每条客观声明可定位到适用依据；有审阅记录 | 缺失/冲突/身份不明时阻止批准；健康安全类未专项审核不通过 | 声明—依据对照、审阅记录 |
| 6. 复测与报告 | 两期分母、流失、共同子集可见 | 无数据不写零；不可比不做变化结论；签发不自动外发 | 报告版本、比对记录 |

### 3.1 跨能力负例（每项都应有）

- 越权读取被拒，拒绝有审计，且不泄露对象是否存在（在适用场景）。
- 重复事件或重复点击不产生重复业务动作。
- 权限撤销后不再交付受影响数据。
- 未获授权的用途（导出、送模型、外发）被阻断，而不是“默认允许”。
- 不可信输入（网页、文件、消息中的指令）不能改变权限或执行规则。

## 4. 里程碑退出门（沿用 M0–M5，不排日期）

| 里程碑 | 退出证据 | 不通过的典型表现 |
|---|---|---|
| M0 范围与资产核验 | 范围、owner、授权与未决项登记完整 | 用页面陈述代替资产核验 |
| M1 需求与设计冻结 | 需求、协议、权限与设计通过评审 | 边做边改口径 |
| M2 纵向切片 | 隔离环境一条链路可运行，含失败路径 | 只有成功演示 |
| M3 六能力闭环 | 正负例、故障与越权测试有记录 | 只测正常路径 |
| M4 业务 UAT 与交付 | 业务签收、恢复演练、运行手册 | 开发自评代替业务验收 |
| M5 运营扩展 | 真实使用数据、事故与成本记录 | 无证据即扩量 |

## 5. 验收记录格式（建议）

| 字段 | 说明 |
|---|---|
| 验收项 ID | 能力 + 类型 + 序号 |
| 场景类型 | 正例 / 负例 / 失败 / 未执行 |
| 前置条件 | 环境、权限、数据与版本 |
| 步骤与预期 | 可复现的最小步骤 |
| 实际结果 | 与预期一致或差异 |
| 证据位置 | 记录、日志、截图或报告的可回看位置 |
| 执行人 / 复核人 | 职责分离；业务或合规项另签 |
| 日期与版本 | 对应环境与产品版本 |
| 结论 | 通过 / 不通过 / HOLD（含原因） |

## 6. 不能算通过的情形

- 只演示成功路径，未验证拒绝与失败。
- 用 mock 或合成数据冒充真实业务记录。
- 模型自评、口头确认、无上下文的截图。
- 跳过、环境缺失或未执行被计为通过。
- 只报平均值或百分比，未报分母、失败与 unknown。
- 演示环境通过后直接声称生产就绪。
