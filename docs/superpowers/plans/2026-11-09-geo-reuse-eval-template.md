# Momcozy GEO：现有资产复用评估记录模板（REUSE-EVAL / ADR）

> **状态：L0 模板，2026-11-09。** 本文件是**空白模板与填写规则**，不是任何资产的评估结论。项目当前没有任何候选资产被评估、被批准复用或被判定不可用。填写前请先阅读[技术与复用讨论稿](./2026-11-08-geo-tech-reuse-discussion.md)的门径与[最小起步授权](./2026-11-08-geo-minimal-start-authorization.md)的范围。

## 1. 使用方式

1. **一个候选资产 + 一个集成边界，一份记录。** 不接受"整体复用 Main"或"整体自研"这类一揽子结论；同一资产可以在入口层复用、在领域层自建。
2. **没有对应授权时，只填"纸面"字段。** AUTH-01 覆盖隔离飞书测试应用的结构性验证（待管理员落实）；AUTH-02 **仅限** T1–T3 的只读元数据、字典与权限信息，**T5 主键契约需数据 owner 书面确认**；**Main 代码只读评估未获授权**，BrandOS 内部数据未获授权。另注意："获得查看权限信息"不等于获得查看、保存、送模型或导出的用途授权。
3. **未填即 unknown，不留空。** unknown 不等于 0、不等于 fail、不等于"资产不存在"。
4. **评估记录不是批准书。** 结论必须由 ADR 承载，并经列明的批准人签署。

## 2. 记录头（必填）

| 字段 | 填写 |
|---|---|
| 记录编号 | `REUSE-EVAL-<候选>-v0` |
| 候选资产 | 名称、系统归属、仓库或路径（未知则 unknown） |
| 集成边界 | 拟复用在哪一层：入口接入 / 事件网关 / 数据契约 / 权限 / 工作台界面 / 其他 |
| 版本或提交 | commit、发布版本、页面快照日期（未知则 unknown） |
| 评估人 / 日期 | 角色 + 日期 |
| **授权编号与范围** | AUTH-01 / AUTH-02 / 其他；写明"只读""仅元数据""含代码"等实际范围 |
| **授权状态** | 已同意待落实 / 已落实 / 已失效；生效日期、有效期、复查日 |
| **授权缺口** | 尚未取得的授权（如"Main 代码读取""T5 主键契约覆盖"） |
| 评估级别 | L0 纸面 / L1 本地 / L2 合成 / L3 经授权的只读或隔离环境 / L3+ 测试租户内的有限实时行为 / L4 明确授权的实时动作 |
| 证据清单 | 每项：来源、等级（A/B/C/D）、日期、能证明什么、不能证明什么 |
| 关联 ADR | `ADR-<编号>`（未决策则留空） |
| 记录状态 | 草稿 / 待审 / 已评估待 ADR / 已决策 / 需重评 |

> 记录中的"判定"只是建议；**正式决定以关联 ADR 为准**。

**证据等级定义（对齐总体计划 §4.5）：**

| 等级 | 含义 | 本模板的典型来源 |
|---|---|---|
| A | 系统记录或批准事实 | 内部系统的字段记录、已批准字典 |
| B | 官方平台政策或已批准规则 | 飞书官方文档、Perplexity 服务条款——**只证明平台规则本身，不证明项目许可、资产能力或适配性** |
| C | 研究资料、公开页面观察、模板、假设 | 资产方/项目方的公开介绍、架构说明、方法论页面（含 Main 公开页面） |
| D | 未核实文本、截图、记忆 | 跨项目记忆、转录材料——**不得作为授权、版本、许可证或适配性证据** |

## 3. 八维评估表

对每个维度分别给出 `pass / partial / fail / unknown / blocked / N/A`，**不做加权总分**。`blocked` 表示权利或授权不允许，必须停止该用途，不得降级为"再看看"。

| 维度 | 评估问题 | 最低证据 | 状态 | 依据与理由 | 未知项 | 阻断范围 |
|---|---|---|---|---|---|---|
| 1. 接口与事件语义 | 同步/异步；请求响应与事件 schema；错误码；幂等键；去重键；顺序；ack 时限；重试与重推；版本兼容；领域对象身份（项目、问句、run、快照、事实、任务） | 契约文档 + 版本 + 样例；事件类需官方文档与隔离环境观察 | 待填 | | | |
| 2. 身份、权限与租户隔离 | 服务端 principal；租户/工作区/项目/对象/动作/用途；群与私聊披露；权限撤销；密钥注入与轮换；共享数据库/队列/存储 | 权限模型 + 威胁模型 + 负向测试（401/403/跨工作区） | 待填 | | | |
| 3. 数据权利与留存 | 逐用途：查看/保存/送模型/内部引用/共享/导出/对外发布；目的限制；保留与删除；跨境；PII | 数据 owner 书面授权（范围、期限、用途）+ 条款 | 待填 | | | |
| 4. 可观测与故障恢复 | run_id / trace_id / message_id；日志、指标、告警；成本、延迟、队列、重试、死信；审计；脱敏；能否区分未执行/失败/unknown/真实零 | 日志与指标 schema、样例 trace、演练记录 | 待填 | | | |
| 5. 维护责任与升级 | 代码 owner；SLA；安全补丁；发布节奏；兼容与废弃；on-call；fork 后维护成本；变更流程 | 具名 owner + 书面承诺或版本策略 | 待填 | | | |
| 6. 许可证与代码可控性 | 许可证与依赖；copyleft 或商业授权；署名；SDK 条款；商标；内部使用授权 | LICENSE/SPDX + 依赖扫描 + 法务意见 | 待填 | | | |
| 7. 退出与迁移成本 | 数据导出与可移植；schema 与 API 耦合；迁移与双跑；合同终止；删除；供应商锁定 | 退出方案、导出格式、迁移步骤 | 待填 | | | |
| 8. 版本与主键契约 | 字段定义、粒度、唯一性、签发方、权限；与 `ai_answer_snapshot_id` 的对齐；不得同名不同义 | 字典 + 样例 + 签发方确认（样例缺失时只能 `partial/unknown`，除非 ADR 记录豁免） | 待填 | | | |

> 第 8 维单独列出，因为它最容易在技术评估中被折进"接口语义"而丢失。未核验前只能写"候选映射"，不能写"已对齐"。该维的授权来源是 **T5，需数据 owner 书面确认**，不自动包含在 AUTH-02 的 T1–T3 范围内。

## 4. 判定规则

| 情况 | 允许的决策 |
|---|---|
| 任一维度 `fail` 或 `blocked`（尤其权限、数据权利、许可证） | 该边界上不得 `reuse` 或 `adapt`；只能 `rebuild` 或 `defer` |
| 存在 `unknown` | 纸面 HOLD，不得写成 `pass`；取得 owner、证据或授权后再升级 |
| `partial` | 可进入 `adapt` / `rebuild` / `defer` 任一选项，但须写明未满足项、可测试的补救条件、退出方案与批准人；**不得仅凭 partial 自动选 adapt** |
| `N/A` | 须逐项说明理由并经确认。N/A 不当作 `pass`，也不单独阻断；全部适用维度 `pass` 且 N/A 已论证时可建议 `reuse` |
| 第 1–8 维全部 `pass`（N/A 按上行处理） | 可建议 `reuse`，仍须 ADR、退出方案与批准人 |
| 跨轨或跨定义汇总 | 不允许；同轨同定义内的分层汇总才需 owner 批准并标口径 |

## 5. 决策选项

| 选项 | 含义 | 必须附带 |
|---|---|---|
| `reuse` | 直接复用 | 版本锁定方式、升级跟随策略、退出方案 |
| `adapt` | 加适配层或防腐层 | 适配层边界、契约差距清单、适配层验收条件、退出方案 |
| `rebuild` | 自建 | 差异理由、替代成本、与既有系统的共存方式 |
| `defer` | 证据或授权不足，暂缓 | 缺什么、谁提供、复查条件 |

## 6. 评估门径（按依赖顺序，不按候选名单）

| 门 | 内容 | 当前可行性 |
|---|---|---|
| G0 授权与 owner 登记 | 每项写明谁能授权哪种动作（读公开文档/读代码/隔离测试/读数据/批准采用）、范围、期限、排除项 | 可做 |
| G1 纸面证据 | 仓库、版本、LICENSE、维护者、SLA、契约文档、数据字典、权限模型 | 仅公开页面层（C 级） |
| G2 契约差距分析 | 接口、事件、数据模型、主键、错误、幂等、ack；只产出差距清单 | 可做纸面部分 |
| G3 安全与数据权利 | 租户、权限、密钥、可观测、逐用途权利、威胁模型 | 纸面部分 |
| G4 受控验证 | 需对应授权。AUTH-01 已同意、待管理员与测试企业落实，只覆盖**飞书测试应用及其结构性验证**；事件接收端的开发/部署、Main/PMO gateway 代码读取均需另行授权 | AUTH-01 待落实；其余未授权 |
| G5 ADR | 按边界决定 `reuse / adapt / rebuild / defer`，写明条件、退出方案、批准人、复核日 | 未开始 |

**适配层验收条件只在决定 `adapt` 之后编写**，不在 G2 阶段预先产出，避免用"适配层"预设结论。

## 7. ADR 模板

```markdown
# ADR-<编号>：<候选资产> 在 <集成边界> 的复用决策

- 状态：提议 / 已接受 / 已否决 / 已替代（被 ADR-xxx 替代）
- 日期：
- 决策人：
- 批准人：（若决策人即批准人，请明示）
- 复核日：
- 关联评估记录：REUSE-EVAL-<候选>-v0

## 背景与范围
要解决什么问题；本次决策覆盖哪一层边界；明确不覆盖什么。

## 候选方案
1. reuse —— 做法、收益
2. adapt —— 做法、收益
3. rebuild —— 做法、收益
4. defer —— 何时可重新评估

## 决策
选择哪一个，依据哪些维度的 pass/partial/fail；未知项如何处理。

## 未选方案及原因
逐项写明，不写“综合考虑”。

## 决策附件
若选 `adapt`：适配层边界、契约差距清单、适配层验收条件。
若选 `reuse`：版本锁定方式与升级跟随策略。
若选 `rebuild`：差异理由与共存方式。
若选 `defer`：缺什么、谁提供、复查条件。

## 影响
数据、权限、运维、成本、人员技能；对既有系统的耦合。

## 风险与缓解
每条风险对应缓解措施与责任人。

## 退出方案
若该决策需回退，如何迁移数据、如何替换接口、需要多长时间（不承诺具体日期，写步骤）。

## 安全与数据权利
逐用途授权状态；哪些用途仍 HOLD。

## 复核条件与日期
触发重评的事件：owner 变更、版本升级、许可证变化、权限变化、安全事件、接口变更。
```

## 8. 填写示例（虚构，仅示范结构）

> 以下全部为虚构，不对应任何真实系统。

| 字段 | 示例值 |
|---|---|
| 记录编号 | `REUSE-EVAL-ExampleGateway-v0` |
| 候选资产 | ExampleCo 内部 Bot 网关（虚构） |
| 集成边界 | 事件接入层 |
| 授权 | 仅公开文档（C 级）；代码读取未授权 |
| 维度 1 接口语义 | `partial`：文档描述了 ack 与重试，未描述幂等键 |
| 维度 2 权限 | `unknown`：未取得权限模型 |
| 维度 3 数据权利 | `unknown`：尚未取得逐用途授权，是否允许送模型未知；在确认前该用途按阻断处理 |
| 维度 5 维护责任 | `unknown`：无 owner 信息 |
| 判定（建议） | 不得 `reuse`/`adapt`；记 `defer`，缺权限模型与数据权利授权；正式决定待 ADR |

该示例同时说明两点：接口看起来合适，但权限与数据权利未定就不能推进复用；**"未知"应记 `unknown`，只有已确认不允许时才记 `blocked`**。

## 9. 本模板不做的事

- 不预设任何技术栈、组件或产品。
- 不把 inbox/outbox、死信等具体实现机制写成先决架构；它们是非功能要求的一种可能实现。
- 不把公开页面当作能力证明。
- 不把其他项目的复用决定、联系人、时间安排继承到本项目。
- 不在未授权时读取代码、接口或内部数据。
