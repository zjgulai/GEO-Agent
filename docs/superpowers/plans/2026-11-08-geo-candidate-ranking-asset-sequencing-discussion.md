# Momcozy GEO 试点：候选商品排序与资产盘点顺序

> **状态：L0 讨论基线，2026-11-08。** 用户在本稿讨论后同意继续：以业务优先、资料调查和逐用途就绪分列，以及先核验一个获准样例再按需扩展，作为后续讨论的方法。具体 ASIN、商业排序、渠道、负责人、用途权限及样例均待业务和相应 owner 确认；这不是最终选品、事实批准或执行授权。资料索取、只读访问、采样、接口接入及外发都未因本稿自动获准。

配套操作表和证据见[商品事实与 PMO 资产只读盘点工作包](./2026-11-08-geo-product-asset-inventory-workbook.md)，测量口径见[问句、采样与指标讨论稿](./2026-11-08-geo-sampling-metrics-discussion.md)。

## 1. 先区分三个顺序

1. **业务优先顺序**：业务/品类 owner 判断哪些美国吸奶器 listing 最值得投入。由经营目标和获准使用的数据决定；不由 Agent 用公开页面多少代选。
2. **资料调查顺序**：在业务候选或调查线索中，先检查哪一个能帮助识别身份、事实及资产缺口。调查先后不等于商业价值高低，也不等于最终入选。
3. **进入某项用途的顺序**：逐个判断身份、事实、时间、审核和该用途权限是否满足。高优先候选的某项事实仍可能暂不可判；资料齐全的低优先候选也不会因此自动变为业务第一。

候选约 3 个 ASIN 只是已同意的讨论方向，具体商品与最终数量由业务确认；不要求为了凑数纳入不适用的变体。无品牌发现是主要测量讨论方向，但其回答级结果不依赖先为每个候选建立独立样本。

## 2. 建议的业务排序规则

### 2.1 先建候选池，不假设现有型号已入选

建议业务先从**美国市场范围内拟纳入 GEO 的吸奶器 listing** 提名，写明渠道、销售或计划状态及判断依据；已有 ASIN 的请提供经授权的定位与 parent/child 区分，没有时保留 `unknown`。不确定现售、市场或渠道适用性的线索可保留待确认，不得自动判为符合或不符合。若业务提名已很明确，不要求扩大至固定数量。

### 2.2 由业务按以下顺序讨论，而非计算虚假总分

| 次序 | 讨论问题 | 所需依据与缺失处理 |
|---|---|---|
| 1. 范围和经营意图 | 是否属于美国吸奶器试点？是否是业务明确关注的商品或计划？ | 商品/渠道 owner 确认范围及截至时间；未知就标待核验，不假定现售或排除。 |
| 2. 业务重要性 | 与当前战略、重点渠道、重点经营商品的关系是什么？ | 可由业务提供排序或经授权的销量、收入等摘要，记录口径、时间窗和适用范围；无数据记 unknown，不推断增长或销量。 |
| 3. 用户决策关联 | 是否对应首期要研究的购物问题、场景或经确认的消费者困惑？ | 优先依据获准的搜索、客服或业务资料；问题只是候选，不假设代表全部消费者。 |
| 4. 候选组合 | 在不牺牲业务重要性的前提下，是否有必要覆盖另一型号，或同型号的重要包装/渠道变体？ | 覆盖差异作为**同等业务优先级时的讨论因素**；不要求强行三种型号，也不因名称不同推定事实不同。 |
| 5. 资源与行动窗口 | 业务、产品、渠道和合规是否能在拟讨论周期参与？ | 记录资源约束与下一次复核；用于安排调查先后，不把暂时无人响应当作商品不重要或自动改动业务排序。 |

建议保留业务方给出的 **P1 / P2 / P3 或同级并列**及理由、依据和截至时间；这只是人工优先级，不是量化模型。若判断依据相互矛盾或均不足，保留并列/待定，由业务 owner 决定，不将缺失值设为零。对每个候选同时标明其来自业务提名、公开资料或其他线索，避免“公开资料较多”变成事实上的入选理由；业务提名也可包含尚未被本项目研究的商品。

### 2.3 单独记录事实就绪，不冲抵业务优先级

对同一候选，分别记录以下状态及原因，不合成一个分数：

- **身份**：listing、型号、变体、ASIN 对应是否被商品/渠道 owner 确认；尚不清楚标 `unknown`。
- **权利**：对拟进行的查看、保存、送模型、内部引用、共享、导出、外发逐项判断；未授权用途停止。
- **事实**：相关属性的来源、范围、有效时间、审批和冲突是否满足指定用途；逐属性判断，不是整款商品统一通过。
- **资源**：负责角色是否已明确，缺口及下一动作是什么。

例如，业务 P1 的商品如包装资料未批准，可继续研究其已获准的其他属性，但不能判其包装声明；不自动把它降为 P3。若需要先验证流程，可暂用经批准的其他候选样例，同时保留业务 P1 的缺口和原优先级。

## 3. 当前建议的调查线索顺序（不是业务排名）

在业务清单到来前，建议先讨论下列**调查顺序**。资料来自此前公开页面观察及本地历史研究，不代表这些商品当前在美国在售、商业重要、已经关联某 ASIN 或被批准进入试点。M5 Smart 和 S12 Pro Quick 产品页在一次独立复核时返回 429；相关既有观察正式使用前需重查。

| 调查次序 | 线索 | 建议先查的原因 | 必须由 owner 决定的事项 |
|---|---|---|---|
| 1 | **M5 Smart，型号层线索** | 已有型号、App/蓝牙和记录方式的来源线索，可作为身份与功能范围的**纸面核验示例**；这不是销量、需求或收益判断。 | 是否是美国试点候选，具体渠道、listing/ASIN、硬件/App 版本及适用事实；若不是候选，停止将其作为试点商品，可仅保留资料线索。 |
| 2 | **S12 Pro / S12 Pro Quick，型号组线索** | 已有零件级兼容性线索，可检查型号与部件是否混淆；这不是两个已确定的 ASIN。 | 业务是否提名其中任一或两者；分别确定 listing/变体及适用的零件证据。 |
| 3 | **业务提名的其他重点 listing 或重要变体** | 避免只选择公开资料较多的型号；可能是另一个型号，也可能是同型号的业务重要变体。 | 业务优先级、纳入理由、渠道及身份；若未知，保持空位而不是臆造商品。 |

M5 可作为核验 M5 Smart 新旧型号关系的**参考线索**；只有业务另行提名后才成为试点候选。上述次序是资料调查建议：业务给出真实优先候选后，应以其顺序为主，公开线索只辅助核验。

## 4. 资产盘点：先一个样例，再按需要扩展

以下为建议的**依赖顺序**，非排期承诺；角色指职责，实际人员待指定。候选提名和资产 owner 寻找可以并行，但读取/处理真实资料之前先确认相应用途权限。

| 步骤 | 谁牵头 / 所需输入 | 操作及输出（对应现有表） | 缺失时 |
|---|---|---|---|
| 0. 范围与权利 | 项目负责人 + 数据 owner；拟用市场、工作区和用途 | 确认查看、保存、送模型、内部引用、共享、导出、外发各自的权限及期限；在 T2 记录逐用途依据，对发布另行核验。 | 权利 unknown 或拒绝的具体操作 HOLD；不把本地 Markdown 当作受限数据默认存储地。 |
| 1. 提名和线索 | 业务/品类 + 商品/渠道 owner；已获准的业务资料 | 业务提出候选及优先理由，登记 T1；仅有型号线索时明确标注层级，listing/ASIN 填 unknown，不靠名称推断。后续查明多个 listing/变体时分别登记。 | 没有明确商品时保留业务候选为空，允许用合成样例核验**结构**。 |
| 2. 发现现有资产 | PMO / BrandOS / 对应数据 owner；经许可的资产元数据 | 找实际资产位置、owner、版本、覆盖、粒度、更新时间及用途；核对 315、62、16、68 的定义，填 T2/T3。 | 只记页面陈述和 unknown；未发现或无权限不能等同资产不存在。 |
| 3. 选一个真实候选样例 | 业务 + 商品/渠道与数据 owner；候选及获准材料 | 优先选业务高优先且可合法查看的一个候选 listing，核验型号/变体/parent-child/ASIN 映射证据、有效时间和审核；填 T1。 | 高优先候选不可查看时，可用另一个获准样例演练结构；业务排序不改。若无获准真实样例，只用合成样例，不能宣称真实资产已核验。 |
| 4. 核对少量属性 | 商品事实/渠道 owner，必要时合规；样例的适用来源与审核记录 | 针对实际候选问题先核查数条：例如功能条件、具体包装清单和渠道保修，逐条记范围、来源、有效与批准时间、冲突和可用用途；填 T4。 | 缺失/冲突/未批准/不适用分开记；只阻断受影响属性与用途。健康、安全、疗效、报销等专项升级合规。 |
| 5. 核验交接含义 | PMO/资产系统 + GEO owner；字典或获准样例 | 纸面确认 T5 中商品身份与事实、`ai_answer_snapshot_id`、内部候选任务的含义、粒度、版本、责任和关联；快照不是事实主键。 | 缺契约记 unknown；不推断接口已接通或已派单。实际接口验证与集成要单独授权。 |
| 6. 小范围评审与扩展 | 业务、商品、数据、GEO 及必要合规 owner | 按候选×属性×用途记录复用/补缺口/缩范围/HOLD，填 T6；再决定是否按同法扩展其他候选。 | 允许部分完成 + 明确阻断；不等于业务验收、生产就绪或通过采样许可。 |

### 4.1 最小样例不是一次全量交付

建议先向相关 owner 索取：①资产及字典元数据；②一个获准候选的身份关联；③针对该候选少量与问题相关、可追溯的事实及其审批/用途；④缺口和联系人。若真实候选未定，以脱敏或合成记录核验结构即可。不得要求凭证、全量导出或超范围个人数据。

同一个 ASIN 的资料是否能用于**判真**、**生成内部草稿**和**对外发布**必须分别确认；允许读不等于允许复制或送模型。`ai_answer_snapshot_id` 的资料核对不依赖现在进行真实平台采样。

### 4.2 商品顺序与品牌发现分母分开

排序决定的是优先核查哪些商品及事实，不把一条回答因关联多个候选而重复计入无品牌发现的回答级分母。仅当问句集合、重复策略、执行与判定规则等保持可比时，候选关联数量变化本身不改变该分母；如果候选变化引起问句或计划变化，观察集合也可能随之改变。获许可且计划获批后，无品牌回答如只提及 Momcozy，不能自动推断具体型号或 ASIN；一条共享回答即使关联多个候选，也只计一次回答级观察。同型号多个变体应标注共同型号及各自差异，不因行数凑成有代表性的多个商品，也不排除业务确有必要研究的变体。具名型号与 ASIN 事实分别按声明和适用身份判断；无身份或事实时记 unknown。具名问题不混入无品牌发现主分母，具体口径仍需审核。

## 5. 如何进入下一步讨论

建议先请业务负责人决定：

1. 按已同意的方法，由业务 owner 提出美国吸奶器重点清单与优先理由；如清单已存在，以其替换第 3 节的暂定调查次序。
2. 按先核验一个获准样例、再按需扩展的方法，确认由谁负责提名商品、确认身份、提供资产元数据及审核事实。
3. 对本次盘点允许的查看、留存和处理范围，由数据 owner 在开展前明确；如果无人或无权限，记录阻断而不是绕过。

用户已同意以上方法作为继续讨论的基线；具体商品、顺序、样例、实际负责人和用途权限仍需相应 owner 明确。每个实际资料请求或外发须由有权负责人另行确认。
