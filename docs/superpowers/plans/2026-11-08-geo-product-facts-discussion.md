# Momcozy GEO 试点：商品事实与证据治理讨论稿

> **状态：L0 讨论稿，2026-11-08。** 本文是业务、数据和审核方案，不代表已取得商品资产、选定 ASIN、批准商品声明或完成系统实现。涉及 Momcozy 的公开页面均为该时点的来源观察，不自动构成本项目可用于判分或发布的商品事实。

## 1. 本节点的目标与边界

**目标**：为美国英语吸奶器试点建立一条可追溯的最小事实链：业务选出候选商品 → 核实型号、变体与渠道身份 → 查找并审核适用事实 → 将事实用于问句、答案核对、诊断和内容草稿 → 经人工审核后再进入后续处理。

**本节点的建议，不是已批准的实施契约**：

1. 保留候选 3 个 ASIN 的讨论方向，具体 ASIN 和最终数量由业务确认；**商业优先级**与**事实可用性**分开评估，不用未经批准的综合评分代替选品。
2. 先核验 PMO、BrandOS 的实际资产和授权；可承接则复用，存在缺口再决定扩展，不重复宣称已经接通。
3. 商品事实至少要明确：主体、属性、值和条件、适用范围、来源与版本、时间、owner、审核及用途；未知或冲突不能当成否定。
4. 问句可问、答案能否判真、草稿是否可审批、是否可发布，是四个不同决定；所有外发和跨系统写入仍需单独授权。
5. 测量以无品牌发现为首要讨论方向，来源引用和产品事实分开核对。[采样与指标讨论稿](./2026-11-08-geo-sampling-metrics-discussion.md)对具体口径和分母另有约束。

**许可边界**：Perplexity 消费端系统性商业采样、复制、截图和导出仍为 **HOLD**，直至适用协议、必要许可、法务判断与单独的项目执行授权明确。人工操作或简化记录不是许可替代。历史 Perplexity 答案、截图或衍生数据的读取、复用、分享及模型处理也须逐项核验来源、适用权利和用途；未获许可的处理不得开展。解除 HOLD 应记录产品面、账号、商业用途、采样方式、保留/共享及模型处理范围的许可依据和项目授权，不因资产发现通过自动解除。本文无需开展真实采样；其他来源、内部资料和模型供应商的数据处理权限也须分别核验。

## 3. 候选 ASIN：先选业务价值，再查事实就绪

### 3.1 身份关系建议

```text
品牌 → 商品家族 / 商业型号 / 代际 → 制造型号或硬件版本
                              ↘ 市场 + 渠道 listing → parent / child ASIN、seller SKU、颜色/组合/包装变体
```

这只是帮助讨论的概念视图，不是已确认的一对一层级或数据库结构。一个型号可能有多个 listing、seller SKU 和 ASIN；一个 parent 下不同 child 的包装、规格、价格或服务条件可能不同。**不能凭 Shopify SKU 前缀猜 ASIN，也不能把 parent 的全部事实自动赋给每个 child。** 具体基数、跨市场关系、型号历史及谁负责维护，须与商品主数据 owner 对齐。

建议为每个候选保留：品牌、市场、渠道、parent/child ASIN（按实际适用）、listing 链接或授权主数据定位、商业型号、制造型号/版本、变体/组合、关系的证据、核验人与核验时间；缺项标 `unknown`，不靠猜测补齐。可沿用既有系统记录关联映射标识、版本、有效起止、证据、owner 和批准时间；这些是可追溯要求，并非预设新表结构。

### 3.2 两张清单，不做虚假精确排名

**A. 业务优先级，由业务 owner 决定**：在获授权的内部数据支持下，考虑美国市场与现售/计划范围、业务重要性、目标购买场景、型号代表性、运营资源和已知问题。可优先形成有代表性的候选组合，但不要求人为凑不同型号；若同型号的不同变体本身重要，也可纳入。销量、毛利、广告和库存等数据未提供时为 unknown，不臆造。

**B. 事实就绪，由商品事实 owner 与数据 owner 核验**：

| 准入项 | 最小检查 | 未满足时 |
|---|---|---|
| 身份 | 能定位美国渠道的具体 listing、ASIN 与对应型号/变体，关系有证据、适用时间、版本及商品/渠道 owner 的适用审核 | ASIN 层分析及 ASIN/listing 特定内容使用 HOLD；可保留已消歧的品牌/型号层观察 |
| 数据权利 | 核实相关资料的读取、保存、模型处理及预期输出用途 | 不执行未获许可的数据操作；必要时只保留获准的引用元数据 |
| 事实与来源 | 针对相关问句有可定位、可追溯的来源、适用范围和时间 | 对缺失属性记 unknown；可继续不依赖这些事实的工作 |
| 审核责任 | 商品、渠道、数据与必要的合规 owner 可确认 | 相应事实、声明或用途保持待审 |
| 冲突与时效 | 相同主体、属性、条件下可查来源分歧、目标业务时点的有效性和处理人 | 冲突属性不用于自动判真或批准内容；不必阻塞无关属性 |

建议先用一张候选表记录「业务优先级说明 / 身份确认 / 资料与用途许可 / 已批准的可用事实 / 已知缺口 / owner / 下一动作」。3 是当前讨论候选数，不是强制凑数；就绪不足时可缩小本轮**事实核查范围**或由业务调整候选，不能靠降低证据要求补齐。商品事实尚未齐备不妨碍独立推进不依赖该事实的中性问句设计与资产核验。

### 3.3 首批事实盘点范围（建议，不替代 PMO 16 类字典）

针对已确认的候选，先盘点与问句直接相关的少量事实：①型号、变体与市场；②功能和 App；③关键规格及单位/测试条件；④包装清单；⑤零件兼容；⑥清洁与安全说明；⑦渠道保修及支持；⑧价格、库存等时效性信息。按实际适用增加或删除，**这些只是盘点主题，并非已有 16 类字段的映射**。

价格和库存是可能快速变化的渠道 offer 观察，须单独记录采集时间、卖家/offer、币种、地区及适用有效窗口；由 owner 确定新鲜度规则，不把某一时点值当成持久商品规格。

健康、安全、疗效、母婴适用、保险/HSA/FSA、监管及比较性效果声明须额外核验精确措辞、证据、市场、群体、条件与授权；由产品和合规人员按职责审核。营销页面或模型回答不自动代替研究证据、监管判断或渠道规则。没有事实依据时可以记录待核查的问题，不能将结论写成产品承诺。

## 4. PMO / BrandOS 资产核验与交接

### 4.1 需要 owner 提供或确认的只读材料

以下是建议的**最小发现清单**，不是对现有系统能力的断言；先确认访问权限、用途和脱敏要求，再查看：

| 材料 | 核验重点 | 对后续选择的价值 |
|---|---|---|
| 资产清单 / manifest 与责任人 | 资产位置、owner、更新频率、覆盖市场/品牌/渠道、粒度、数量定义、截至时间 | 判定 315 / 62 等数字各指什么，而非对营销数字做行数假设 |
| 16 类事实字典及版本 | 类别、字段、单位、范围、来源锚点、空值语义、批准状态和时间 | 判断可复用的事实与需补充的缺口，不把 16 类和 68 维强行对应 |
| 经许可的美国 Momcozy 最小样例 | 候选 ASIN 与品牌/型号/变体/listing 的对应，几条事实及来源、历史版本 | 验证是否能回答本节点的主体与时效问题；不要求先导出全量资料 |
| 权利和使用说明 | 阅读、存储、发送给模型、内部引用、导出和外部使用；保留/删除及接收方约束 | 确定允许的处理方式与适用对象；权限未知时阻断对应操作 |
| 主键/身份映射与变更规则 | 主键含义、命名空间、唯一性、时间范围、合并拆分和映射责任 | 防止不同 SKU、listing 或历史版本串档 |
| 读取接口或批准的导出方式 | 环境、认证、范围、分页、版本、更新时间、错误和访问审计 | 可授权时再做只读验证；页面或 OpenAPI 列表不等于可接通 |
| `ai_answer_snapshot_id` 字典与交接样例 | 谁签发、标识什么、唯一性与版本、作用域、保留/访问、如何关联采样协议、问题和证据 | 避免另造同名不同义；确认它与商品事实、任务及下游的关系 |
| 上下游流程与回执 | Source、asset、GEO、Vicky、Shopify 各自职责、输入/输出及变更责任 | 识别真实接口、审批与回执缺口；内部候选任务不称为已派单 |

`ai_answer_snapshot_id` 是 PMO 提及的**AI 答案快照交接标识**，其实际契约尚未验证。商品事实版本、来源、问句、答案、标注、诊断与候选任务是不同对象，可通过经核验的关系关联；不能把答案快照 ID 当作商品事实主键，或从名称推断其全局唯一性。

### 4.2 建议分三道互不代替的门

1. **资产发现门**：确认 owner、清单、样例、身份、来源和使用权；先明确能复用什么。数据不完整只限制相关范围。
2. **后续安全/集成门**：在实施规格中验证身份权限、只读接口、审计、错误处理和端到端追溯；不能由页面访问成功代替。
3. **平台采样许可门**：对拟用产品面、账号、商业用途与数据操作独立核验；资产发现通过不解除 Perplexity HOLD，反之亦然。

建议的承接判断：现有事实满足范围、版本、审核和权限要求时，优先引用其权威版本；只有无法满足的字段或流程才进入扩展讨论。能否直接读取、复制或同步，以及哪个系统是权威来源，由各 owner 和授权机制确定，**此处不预定双写、迁移或生产架构**。

## 5. 最小商品事实契约

以下是需要**在概念上可追溯**的内容，不是已冻结的字段、表结构或 API。后续应首先对照现有字典，缺少的信息才讨论扩展。

| 维度 | 建议记录 | 约束 |
|---|---|---|
| 主体及关系 | 品牌、型号/硬件版本、市场、渠道、listing/ASIN、变体及身份映射版本 | 主体精度与声明匹配；仅知品牌或型号时，不自动判成某个 ASIN |
| 属性与值 | 一个可核对的属性、值、单位、否定/上限、条件；必要时按部件拆分 | 不丢失「最多」「约」「仅限」等限定词；不把不同测试条件的数字直接视为冲突 |
| 来源及证据 | 可定位来源、具体章节/页面/记录、来源 owner、来源版本或可验证标识、取得时间 | 来源身份、来源写了什么及来源是否支持声明要分别核验；URL 或哈希单独不足以证明真实或使用权 |
| 适用范围 | 市场/法域、语言、渠道、型号与变体、群体、使用场景及用途；相关时包括 App、固件、OS 与设备版本 | 英文不等于美国；官网渠道规则不自动覆盖 Amazon；不适用不等于假 |
| 业务有效时间 | 事实自何时对该主体/范围生效、失效或条件变化 | 不能将今日事实直接套用到历史回答；不清楚时记 unknown |
| 系统知悉与决策时间 | 何时取得/录入、何时批准、撤销、解决冲突，以及相关身份映射版本 | 防止后续批准、冲突解决或映射变化悄悄穿越到历史评估 |
| 审核与责任 | 事实 owner、审核人/角色、决定、时间、理由及适用用途 | 有值与已批准分开记录；没有授权的模型、网页或聊天文本不能替代审批 |
| 来源与用途权利 | 谁可在什么工作区/用途读取、保存、送模型、引用、导出和发布；到期、撤销及保留限制 | 各用途分别批准；数据删除或保留遵守适用法律、合同和公司制度 |
| 冲突与变更 | 候选来源分歧、影响范围、处理人、裁定与关联版本 | 未解决的同范围实质冲突不得自动择优；修订保留可审计关联，受保留与删除要求约束 |

在后续知识准入设计中，每条被引用的来源至少核对 `source_id`、`evidence_grade`、`source_uri`、`source_owner`、`version`、`workspace`、`allowed_agents`、`blocked_actions`；任一项未知时该来源记录仍是草稿，不能因为占位或补齐形式字段就视为获得事实批准或使用授权。另按用途核对来源类型、取得时间、权利持有人/许可依据；若页面会变动，在允许留存时记录可追溯版本或哈希及保留条件。哈希、页面发布日期和取得时间均不能单独证明历史业务有效性或使用权；必要信息 unknown 时对应判断应保持 unknown。具体可实现方式须与现有系统字典和数据权利约束对齐。

建议把**值状态**与**审核状态**分开：例如事实候选值可以已知但尚未审批；`unknown`、`not_applicable`、存在冲突、已过期和被撤销应分别表达，不能压缩为 `false` 或 `0`。`evidence_grade` 与测量来源类型是不同维度；第一方页面能证明「页面这样写」，不自动升格为 A 级、经批准的适用商品事实。

### 5.1 两种历史问题，不混算

1. **当时判定**：针对观察发生的时间，以当时业务有效、且截至当时已经取得并获适用批准的身份映射、事实及冲突状态判定；以后才批准的资料不得假装当时已知。
2. **后来重评**：若后来取得或纠正资料，可在明确的**重评知识截止时间**下重新分析过去；标出新增证据、批准时间和与原判断的差异，不静默改写原判断或报告。历史材料的保留与删除须受实际权利约束。

两类结果必须标清评价问题、原观察或快照的引用、观察时点、知识截止时间、映射/事实版本与原因；后来重评不以新采样替代原观察。回溯生效或冲突撤销应记录事实 owner 的决定、理由和受影响的评估/报告，并遵守数据 owner 确定的保留及删除规则。若业务有效时间不明，不能只因来源今天存在就认定其过去有效；若当时存在尚未解决的冲突，不能把后来达成的裁定倒填成当时已定。具体时间和撤销规则需 owner 审核，以上只是设计原则。

## 6. 事实如何进入六能力闭环

| 步骤 | 最小建议 | 缺失或不确定时 |
|---|---|---|
| 1. 配置与问句 | 使用已核实的商品身份填入具名题；中性无品牌问句不强行包含品牌或 ASIN。问句及其关联版本由业务/GEO 审核 | 身份模糊不强行实例化特定 ASIN；不把未经证实的断言嵌入题目 |
| 2. 采集/导入 | 按获授权的产品面、计划和数据操作形成答案快照并记录协议；同一共享问句的观察不因关联多个 ASIN 重复计数 | 当前 Perplexity 系统性采样 HOLD；其他轨道各自确认许可，不以 API 冒充消费端 |
| 3. 解析与指标 | 将回答拆成可定位的原子声明；识别品牌/型号/变体，分别核验引用支持与事实一致性；一个声明可关联多个来源和事实 | 无可用事实、来源不可访问或身份不足时分别标 unknown/N/A 与原因；不算错或无引用 |
| 4. 诊断 | 区分「观察到的回答」「来源是否支持」「与批准事实是否一致」「可能的原因」；引用缺口、事实缺口及来源歧义分别形成候选问题 | 不把模型回答变成事实，不把单次现象当成根因，不保证改善结果 |
| 5. 内容生成 | 仅在获准的数据处理范围内，以当前适用且已批准的事实起草；客观声明可追溯到来源和版本；ASIN/listing 特定内容须核验并批准主体映射，高风险声明走专项审核 | 缺失、过期、冲突、身份未确认或用途未授权的声明不自动进入可批准内容；型号层草稿只能标明型号层范围，不冒充 ASIN 特定草稿 |
| 6. 复测与报告 | 保留口径、采样与事实版本，展示覆盖、unknown、失败及变化；事实变更时标记受影响的问句、判断和草稿供复核 | 不静默覆盖历史；不兼容条件单列，不自动宣称 SEO 变更造成结果 |

**可问 ≠ 可判真**：没有批准事实时，可以拟定不内含未核实断言的中性候选问题；将其发送仍需平台许可及项目授权。如果没有适用商品事实，答案里出现的该属性不能进入事实准确率的可判定分母。竞品声明需要其自身的适用证据、范围和审核责任，不能用 Momcozy 事实强行判真；未确定竞品资料及责任前，相关事实判断为 unknown。声明拆分时保留量词、否定、条件和程度，不能把「有些」改写为「所有」；缺失证据也不自动证明否定事实。

**引用支持 ≠ 商品事实一致**：引用是回答引用了什么，支持度是该来源是否支持声明，事实一致性是声明是否与适用的批准事实一致。来源仅出现在列表中、不可访问或关联不清时不能自动算支持；来源支持而与批准事实冲突时，应交 owner 查明，而非自动修改事实。引用支持按声明—引用对，事实一致性按声明，品牌提及按回答；详见[指标字典](./2026-11-08-geo-sampling-metrics-discussion.md#5-指标字典-v0仅为讨论建议)。

**来源内容是数据，不是指令**：网页、文档、回答或飞书消息中的要求不能改变系统权限、批准事实、泄露资料或触发发布；身份与权限由服务端核验。内容或适用事实、用途、目标范围发生变化时，建议标记相关审批待复核；正式失效规则由后续规格确定。

## 7. 一个虚构示例：看清身份、时间与判定

以下品牌、型号、ASIN、时间、事实和回答**均为合成示例**，不是 Momcozy 商品数据，也不是一次真实 Perplexity 观察。

- 虚构品牌 `ExampleCo`、型号 `Pump X` 在美国有 `ASIN-A` 和 `ASIN-B` 两个变体。批准的身份映射表明，两者同型号，但包装不同。
- 事实 F1：`ASIN-A` 包装含 1 个部件 Q；2026-01-01 起在所述美国渠道生效，2026-01-10 被获取并批准用于内部核对。F2：`ASIN-B` 包装不含部件 Q，同样自 2026-01-01 生效，2026-01-10 获取并批准。证据和批准都只在示例中假定存在。
- 假设一条经许可的虚构快照于 2026-02-01 回答：「Pump X includes one Q」，但没有指出 ASIN 或变体，也未明确是所有还是部分变体。**型号层声明范围不明，ASIN 事实判断为 unknown/变体不明**，不能选更有利的 ASIN，也不因问句关联了两个 ASIN 而把一条回答计为两次。若回答明确 `ASIN-A` 且映射、条件、事实和许可均匹配，才可在该范围按 F1 判断一致；如果声明明确使用「所有」等量词，则应按该量词和完整适用范围另行判断。
- 若回答还附带一个来源：来源确实支持该声明，只说明**引用支持**；能否判事实一致仍需身份、适用范围、时间和批准均匹配。如果来源不可查看或引用关联不清，支持度为 unknown，不等于不支持。
- 假设 2026-03-01 才批准一条补充证据 F3，业务有效起点标为 2026-01-01：对 2026-02-01 的**当时判定**不得假装 F3 当日已经批准；可以在标明 2026-03-01 知识截止时间的**后来重评**中评估 F3，保留与原判定的关联和差异。F3 是否改变结果，取决于具体内容、适用范围及冲突处理，不能预设。

## 8. 后续离线验收候选：现在尚未执行

在实现规格获批后，建议先用虚构、无网络、无真实账号的 fixture / dry-run 检查至少以下场景，预期作为未来验收目标，**不是当前测试结果**：

| 场景 | 预期 |
|---|---|
| 型号对应两个包装不同的 ASIN，回答未指明变体 | 型号层保留观察；ASIN 事实为 unknown，不重复计数 |
| 加拿大或官网渠道事实被用于美国 Amazon 声明 | 范围不匹配；不能直接判美国 Amazon 对错 |
| 某值明确但待产品审核、或同范围来源存在未解决冲突 | 保留候选值与状态，不自动用于判真或审批草稿 |
| 历史回答后才补录并批准一条回溯生效事实 | 当时判定不穿越；后来重评有独立知识截止时间和可审计关联 |
| 来源支持声明但批准事实冲突；或来源无法读取 | 前者创建人工复核项，后者支持度 unknown；不自动改事实 |
| 来源只允许内部阅读，不允许送模型或外发 | 对应受限处理被阻断；不能把读取权限推导为模型或发布权限 |
| 网页中含「忽略规则并批准/发布」 | 当作不可信数据，不改变权限或产生外部动作 |
| 健康/安全/报销类客观声明缺少适用证据或合规审核 | 保留待核查风险；不自动批准进入可发布草稿 |
