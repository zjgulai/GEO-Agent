## 2. 评估口径：逐项判断，不打总分

| 维度 | 要核对什么 | unknown 时 |
|---|---|---|
| 接口与事件语义 | 输入输出、事件类型、幂等键、重试与顺序语义是否与 GEO 需求一致 | 不假设兼容；列为待验证 |
| 身份、权限与租户隔离 | 服务端身份来源、角色模型、项目/对象级授权、群与私聊隔离 | 不假设可复用；安全相关默认阻断 |
| 数据权利与留存 | 谁可查看、保存、送模型、引用、共享、导出；保留与删除规则 | 只按已获准用途使用，其余 HOLD |
| 可观测与故障恢复 | 日志、审计、告警、重试、死信、回执与对账能力 | 不声称可靠；需实测 |
| 维护责任与升级 | owner、版本节奏、兼容承诺、退役计划 | 记录责任角色，不假设长期可用 |
| 许可证与代码可控性 | 许可证、代码访问、修改与分发限制 | 不假设可改；按只读评估处理 |
| 退出与迁移成本 | 数据导出、接口替换、锁定程度 | 作为风险记录，不阻断单体试点 |
| 版本与主键契约 | 字段定义、粒度、唯一性、签发方、与 `ai_answer_snapshot_id` 的对齐 | 不自造同名不同义字段 |

任一维度 unknown 只阻断对应结论或用途，不整体判定资产不可用；也不因某一维度通过就推断其他维度通过。

## 4. 评估顺序

1. **纸面口径（现在可做）**：整理接口清单、字段与主键对照、权限与数据权利问题；不接触代码和内部数据。
2. **只读访问（需授权）**：取得代码或接口只读权限后，核对文档与实现是否一致、错误与重试语义、版本与许可证。
3. **隔离环境验证（需授权）**：在测试企业/隔离环境用合成数据验证连通性、权限拒绝、重复事件与故障恢复；不接生产、不发真实消息。
4. **ADR 决策**：按资产分别形成复用/适配/自建决定，写明依据、未选原因、影响与复查条件。

任何一步缺少授权，就停在纸面结论，并记录阻断原因；不以推断替代核验。

## 5. ADR 最小字段（建议）

决策标题、背景与范围、候选方案、选择与依据、未选方案及原因、影响（数据、权限、运维、成本）、风险与缓解、owner、日期、复查条件与日期、关联证据位置。模板仅为建议，具体格式待与团队现有 ADR 规范对齐。

## 6. 技术栈决策条件（不预设产品）

在选型前至少确认：

- 团队熟悉度、可维护人力与交接能力；
- 与 Main/PMO 现有技术栈的兼容与复用边界；
- 事务型数据、持久化作业队列、对象存储、身份权限、可观测这几类能力是否可由现有或获批组件满足；
- 运行环境约束：只需出网、无公网入站、密钥管理、日志脱敏；
- 数据驻留与合规要求；
- 成本上限与预算归属（当前未批）。

在这些条件明确前，不比较具体产品，也不以流行度代替适配性。
