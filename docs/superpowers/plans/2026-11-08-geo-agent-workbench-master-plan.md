# Momcozy GEO Agent 与工作台 0→1 总体实施计划

> **状态：L0 讨论稿，尚未批准实施。** 本文是跨子系统的路线图和验收草案，不是已冻结、可直接编码的逐文件实施计划。各节点经讨论确认后，分别生成独立子项目规格、逐文件任务、接口、测试及执行计划。对于获批准的实施子计划，再按 `superpowers:subagent-driven-development` 或 `superpowers:executing-plans` 逐任务执行；当前不授权自动开发、部署或发布。

**Goal:** 为 Momcozy 建立以证据为核心的 GEO Agent 与工作台，覆盖问句、采集、解析、诊断、内容建议、复测报告的闭环，并以飞书群 @、单聊和交互回调承接业务。

**Architecture:** 工作台与飞书是两个交互入口，共享受权限约束的业务服务、Agent 能力和数据契约；采集、生成及复测经持久化任务异步执行，重要结论均能回溯快照、事实和版本。先验证 Main/现有 GEO 的底座与授权，再决定复用或自行实现；不以页面描述替代代码和运行环境核验。

**Tech Stack:** 未决。建议比较 Main 现有栈与团队能力后决定；逻辑上需要事务型数据库、持久化作业队列、对象存储、服务端身份权限、可观测平台、飞书官方 SDK 和可替换的模型/探针适配层。本文不预先指定云厂商、语言、框架、模型或供应商。

## Global Constraints

- 本轮仅产出调研和方案；未经授权不进行付费模型调用、应用配置变更、外部发送、网站修改、发布、投流、上线或提交推送。
- 首期服务 Momcozy；未来多品牌是可扩展设计，不预设已批准的多租户 SaaS。
- 对已出现于会话的飞书 App Secret，建议管理员在实际接入前轮换；凭证仅经密钥管理注入，不写入仓库、文档、浏览器、提示词或日志。
- 所有建议性范围、样本数、时长和指标阈值均待业务负责人确认；不得把建议写成既定预算、排期或已实现能力。
- 母婴、健康、疗效、安全、保险报销、市场适配与授权等声明必须绑定有效依据并由授权人员审核；不自动对外发布或修改 Shopify。
- 平台第一方聚合、真实消费端受控观察、API 代理观察、站点第一方日志、站点分析和第三方估计分账；未知、真实零、未采集、采集失败、不可用不得混为一谈。
- Agent 不得仅凭 AI 答案确定品牌事实；缺证据或授权时明确拒绝、降级并交由人工处理。
- 工作台在线、静态演示和本地测试不等于业务验收或生产交付；每项能力须有可回溯的验收证据。

## 1. 业务目标与现状基线

### 1.1 问题与产品承诺

**目标用户**：品牌搜索/GEO、内容与 SEO、商品与 Shopify、媒体公关、产品/客服、合规审核、业务负责人和运营人员。

**要解决的问题**：团队需要知道在指定国家、语言、平台和购买场景中，Momcozy 与竞品是否被提及，哪些来源被引用，产品事实是否准确；基于可核查证据形成可执行的品牌事实、页面或媒体协同任务，并在相同口径下复测。Agent 让业务人员在飞书发起查询和查看结果，工作台承接配置、审阅、分析、任务与报告。

**一句话承诺（草案）**：给定经批准的市场、SKU、购买场景和采样方案，系统产出带原始证据、覆盖边界、待办和责任人的 GEO 诊断；经人工处理后，使用版本冻结的条件复测并报告变化与不确定性。

**否定条件（供需求访谈验证）**：如果一次指定样本的结果不能追溯到原始回答/导入文件与其采样条件，或无法区分采集失败与真实未出现，则该次诊断不合格；如果用户未经许可即可访问其他群/项目数据或发起外部发布，则不准交付。

## 2. 产品范围与首期建议

### 2.1 工作流与用户角色

| 角色 | 主要工作 | 首期动作边界 |
|---|---|---|
| GEO/SEO 运营 | 配置问题、发起采样、审阅答案、发起复测 | 管理被授权的项目和样本；不能直接发布外部内容 |
| 内容/商品运营 | 查缺口，生成与修改建议，准备页面变更 | 编辑草稿，提交审核；不能绕过产品事实/合规门 |
| 产品/客服/渠道 owner | 审核 SKU、型号、市场、功能、版本与服务事实 | 对所属事实批准、驳回和设置有效期 |
| 法务/合规 | 审核健康、安全、报销与营销宣称 | 审批或拒绝；不代替事实 owner |
| 公关/Vicky 与 Shopify 执行方 | 接收任务、补证据、登记落地结果 | 先人工确认任务；系统间写入须另获授权并验签/校验回执 |
| 业务负责人 | 定范围、样本、资源、上线与效果目标 | 审批范围和生产验收，不以 Agent 自评代替 |
| 系统管理员 | 应用、权限、密钥、审计与运行 | 最小权限；生产变更按流程审批 |

**以下为基线下的细化建议，尚待逐项确认：**

1. **品牌/市场**：Momcozy、美国英语；首期品类为吸奶器。
2. **SKU 与问题**：候选 3 个 ASIN，权威事实资料及其适用性须另行核验；按 PMO 的 20 问/ASIN 方向建立候选问句，具体 ASIN、问题数量及重复次数待批准。问题覆盖无品牌发现、比较、购买场景、型号核查，是否适合各 ASIN 由业务审阅。无品牌问题可以与多个 ASIN 关联，计划观察数以去重后的实际执行清单为准。
3. **入口**：Perplexity 真实消费端优先。当前系统性商业采样、复制、截图和导出均为 **HOLD**：须先核验适用条款、其他适用协议、必要的平台许可与法务判断，并取得项目执行授权；人工操作或简化记录并非许可替代。详见[采样与指标讨论稿](./2026-11-08-geo-sampling-metrics-discussion.md)。如入口不可用，则等待或另行决定，不以 API 响应代替；若后续获授权验证 API，必须标为独立代理轨道。
4. **样本示例**：若 3 ASIN 各自拥有 20 条**互不相同**的问题，在同一入口各重复 2 次，即 120 次计划观察——这是完全不共享时的朴素上界，不是计划数或预算；若存在共享问句，按去重后清单计算（采样稿的 68 示例为 13 条共享 + 每 ASIN 7 条独有的假设）。实际执行次数以冻结且去重的清单为准。失败、未执行、平台未触发及有效答案均留痕。重复次数仅用于试点可操作性，不足以承诺统计代表性；预算和条款未获批准前不调用付费服务。
5. **功能**：建议建立项目和问句版本；在授权条件下登记/导入样本及事实；解析品牌提及、来源、Best Overall 和事实状态；提出待审内部候选并由人确认或驳回；探索有证据的草稿、人审及可比复测。处理结果记录及工作台与飞书查询同一任务只是后续建议，真实任务的创建、指派和记录方式尚未批准。
6. **外部动作**：首期任务卡只生成待审批/待导出记录，Vicky、Shopify 或 PMO 写入均需另行确认授权、接口和幂等回执；邮件、媒体接触、网站发布、投流默认禁止。

**非 MVP**：全量 315 SKU 接入、所有市场与所有平台、自动编辑官网/投流、多品牌自助开通、无人工监督的自动 SOP 变更。架构可保留扩展点，但不以此拖延试点。

## 3. 六项能力图谱与验收草案

每项能力应先锁定 owner、输入/输出、错误、权限、业务验收人和可失败检查；表内指标是**建议验收条件**，不是已测结果。

| PMO 能力 | 具体建设 | 关键输入 → 输出 | MVP 最低验收 |
|---|---|---|---|
| 1. 配置与问句库 | 品牌/市场/ASIN、竞品别名、场景标签、问题版本与冻结；飞书高频问题进入候选队列 | 已授权品牌事实 + 提问 → `prompt_set_version`、待审候选 | 可创建、审阅、冻结和回看；修改生成新版本，不覆盖历史；问题不得私自成为正式基线 |
| 2. 采集探针 | 人工导入和经授权的适配器；执行计划、配额、重试、失败记录 | 问句版本 + 入口/环境 → run、原始回答/截图或响应、状态、元数据 | 截止时每个计划项有明确状态；有效/失败/未执行可区分，未执行不冒称终态；记录权限、地区、入口、时间、成本；导入证据可回看 |
| 3. 解析与指标 | 品牌/别名与 SKU 消歧，来源抽取，规则/模型解析，人审与指标字典 | 原始快照 + 规则版本 → 结构化标注与可追溯指标 | 解析无把握输出 unknown；每个数可钻取至快照；分母守恒；纠错保留原始版本并重新计算 |
| 4. 诊断洞察 | 分开记录观察、核查、假设及建议；提出内部待审候选 | 获准样本及相关事实/页面资料（可缺失）→ 诊断与候选建议 | 无样本不声称实际表现；品牌提及诊断不要求商品事实齐全；缺证据或事实时标 unknown，建议角色与进一步处理方式待定，不将候选视为派单 |
| 5. 内容生成 | 建议基于经批准且允许用于该用途的事实形成 FAQ/PDP 等内部草稿；声明逐条绑定证据 | 生效且获准的事实 + 适用的内容需求或诊断 → 可追溯的草稿及待议审阅记录 | 客观声明有可核对的适用证据；缺失/冲突时不能批准受影响声明；健康/安全/报销走专项审核；不自动外发或发布 |
| 6. 复测与报告 | 版本比较、任务结果、定时建议、人工签发与导出 | 基线 + 处理记录 + 复测快照 → 报告 | 原方案、时间、样本、失败数、口径和变化可重现；不兼容版本禁止直接同比；报告含结论边界与审阅人 |

**共用安全门**：RBAC、群与私聊隔离、审计、来源校验、禁止提示注入执行、成本控制、人工审核。跨 Agent 移交的最小建议字段：`snapshot_id`、项目/品牌、市场/语言、问题版本、任务与证据引用、申请人、授权/批准状态、目标 owner、幂等键与回执；`ai_answer_snapshot_id` 需与 PMO 主键字典对齐而非另造同名不同义。

### 4.1 六条不可混用的数据轨道

### 4.2 问句与采集协议

- 给每条问题记录 `prompt_id`、版本、问题原文、品牌显式/无品牌、购买意图、国家/语言、相关 ASIN/品类、适用性、owner、批准时间和禁用记录；同一文本有修改即产生新版本。
- 冻结采样清单、入口、地区、语言、设备、账号/登录状态、执行者或自动化来源、问句顺序、采样窗口、重复次数、竞品别名和提取规则；记录无法控制或未公开的模型版本，不猜测。
- 每次重复默认新开独立对话并避免携带前一答案；记录 `session_id`、上下文是否重置、账号历史/个性化状态（未知时标 unknown）及重复间隔。新会话仅消除显式会话上下文，不保证账号、时间或模型层面统计独立；若平台不能新开对话，保留上下文并作为不同协议，不能假装独立重复。
- 真实消费端仅采用平台条款允许且获授权的方式；不得绕过登录、验证码、访问限制或冒用地区。人工与自动来源分开存档。
- 区分 `not_run`、`failed`、`valid_answer`、`valid_no_feature`、`invalid` 及执行中的中间状态；`planned` 指冻结计划中的全体项（含已执行项），不是互斥状态。每个计划项在报告截止时必须恰落入五类之一，或明确列为仍在执行，保持总数守恒；记录失败原因/超时/限额/未触发及原始证据，不把 `valid_no_feature` 写成「品牌未被提及的有效答案」。
- 获许可后按协议重复抽样，并在许可范围内保留原始答案与引用；样本量很小时展示 `x/n` 和可授权回看的原始数据，避免高精度百分比；若要推断总体或因果，需另行设定抽样框、统计方法及适用条件。

### 4.3 核心指标字典（待业务批准的 v0）

所有指标都分层展示平台/产品面、轨道、市场、语言、问句集版本、采样窗口、规则版本及分子分母；不跨定义聚合。

| 指标 | 建议定义 | 分母与例外 |
|---|---|---|
| 计划项终态率 | `(valid_answer + valid_no_feature + invalid + failed) / planned` | `not_run` 不进入分子；该指标衡量是否处理到终态，并非质量合格率；所有终态需有记录 |
| 答案或未触发覆盖率 | `(valid_answer + valid_no_feature) / planned` | 该名称不表示均有可分析答案；`invalid`、`failed`、`not_run` 各自单列，均不当品牌提及率负样本 |
| 有效回答覆盖率 | `valid_answer / planned` | 计划项为分母；只统计有可用回答，不含未触发和无效项 |
| 功能未触发率 | `valid_no_feature / planned` | 未触发指已确认该入口未出现目标 AI 功能，并非未提及品牌；与失败/未执行分别报告 |
| 品牌提及率 | 答案中经别名消歧明确提及 Momcozy 的有效回答数 / 可判断品牌是否提及的有效回答数 | 未触发、失败、无法判定不加入分母；unknown 数另报 |
| 官方来源引用率 | 至少一个来源命中经核实官方域名/URL 映射且实际被答案引用的有效回答数 / 可判断引用的有效回答数 | 普通文本提及 URL 不自动视为引用；无来源功能及无法解析另报 |
| 声明支持度 | **声明—引用对级**：来源充分支持的已判定配对数 / 已判定配对数 | 部分支持、不支持、反驳与 unknown 分列；缺原文、不可访问或关联不清为 unknown，不计入已判定 |
| 型号事实准确率 | 与观察时点业务生效且适用市场/型号、并符合指定知识截止时间的已批准事实逐项对照后，判定正确的声明数 / 已判定的声明数 | 事实冲突或过期时 unknown；不以 AI 答案作事实来源；区分当时判定与后补证据重评 |
| Best Overall 观察率 | 对适用的比较问题，回答以明确、可审阅的「总体最佳/首选」语义指向目标品牌或 SKU 的有效回答数 / 可判定的适用回答数 | 只提及品牌、列表首位、单次正面描述不自动算；无比较意图/未判定单列；规则由业务审定 |
| 变化 | 同轨道、同入口、同市场、可比版本下，两期指标值和计数的差 | 保留原始 `x/n`；问题/入口/规则改变先显示不可比或双轨桥接，不暗示因果 |

**检验优先级**：明确观察事实 → 把潜在原因标记为假设 → 写行动与预期 → 记录执行/同时发生的变化 → 复测。可设计同期对照与预注册，但小样本或平台变化会限制因果解释。GSC、GA4、订单、爬虫日志分别记录口径和时区，不拼接成未经验证的 ROI。

### 4.4 数据实体与血缘

建议概念模型，实际类型/约束在设计阶段固化：

下图仅表达概念依赖，不代表严格线性流程或一对一基数：商品事实与问句、回答声明可通过多对多关系关联；有些共享问题只关联品类，候选任务也不一定要求商品事实齐全。

```text
Brand / Workspace → Market / Locale → Product / ASIN → FactVersion
                                  ↘ PromptSetVersion → ProbePlan / Run → AnswerSnapshot
AnswerSnapshot → AnswerClaim / Citation
AnswerClaim / Citation + 适用的 FactVersion（可缺失） → Annotation → MetricVersion → Diagnosis
                                                                → Task / Approval → ContentDraft → Retest / Report
```

`FactVersion` 与 `AnswerClaim` 是不同对象：前者为有来源、范围与审核状态的商品事实版本；后者为从 AI 回答拆分的声明，不自动构成商品事实。

- `AnswerSnapshot`：对齐 `ai_answer_snapshot_id`；带执行任务、来源轨道/入口、采样时间与环境、原始对象引用及哈希、状态、失败原因、解析/规则版本。原始答案与截图的存储/展示须遵守权限与保留期限，不把敏感内容写审计日志。
- `MeasurementRecord` / `SiteLog` / `ThirdPartyMeasurement`：按实际来源记录上述 `measurement_source_type` 枚举、范围、时间窗、数据 owner、原始文件引用、处理版本和权限；站点日志还记录路径、状态、时间、自报 UA、来源身份核验结果与方法版本。原始 IP 仅在必要时受控保存，并遵循最小化、访问控制和保留政策；第三方测量记录供应商方法、样本、范围与不确定性。日志/第三方实体不强行伪装成 AI 答案快照。
- 抓取与资格审计记录 robots、索引、摘要资格、Search generative AI 控制及可用的真实日志证据；结果分别标已确认、未确认或不适用，配置、访问、收录和引用不能互相替代。首期能否取得站点日志或平台权限待 owner 确认；无权限时记录 unknown，不能虚构。
- `FactVersion`：产品/ASIN、市场、语言、事实版本、有效期、来源锚点、产品 owner、批准状态和相互冲突记录；标明允许用途及是否可用于外部发布。`AnswerClaim` 关联原始回答位置和人工判定，不自动成为 `FactVersion`。
- 每条入库知识应有 `source_id`、`evidence_grade`、`source_uri`、`source_owner`、`version`、`workspace`、`allowed_agents`、`blocked_actions`；缺字段仅作为草稿，不得用于高风险发布。`evidence_grade` 是第 4.5 节的知识证据等级，与测量轨道 `measurement_source_type` 是不同维度；来源轨道不自动决定证据等级。
- `Citation` 保存原始 URL、规范化 URL、域名归属核验状态、展示片段/位置、实际来源与可达性；不可仅凭域名相似断言官方或假冒。
- `MetricVersion` 固化公式、分子/分母、时间窗、适用群体、缺失规则、代码版本、变更人；数字可反查原始记录和处理版本。
- `Task/Approval` 保存责任人、许可与声明 gate、幂等操作、状态流转、回执与复测链接；历史追加而非静默覆盖。涉及隐私的原始数据可依法按保留政策删除或匿名化，审计留存最小必要元数据，避免把「原始数据永远不可删除」当成绝对规则。

### 4.5 证据等级与结论契约

- **A 系统记录/批准事实**：可证明某系统在某时记录了什么，不自动证明页面陈述背后的业务事实为真。
- **B 官方平台政策/已批准规则**：证明对应平台在指定日期的规则，适用范围不得外推。
- **C 研究资料/公开页面观察/模板/假设**：可做候选依据；对于第一方公开页面，该级仅描述观察到的页面内容，需再核验适用性、用途许可与业务审核，不自动成为批准的商品事实。
- **D 未核实文本/截图/记忆**：不得作为发布或验收结论。

每条重要输出携带 `conclusion`、`evidence`、`assumptions`、`uncertainty`、`confidence`、`blocked_actions`、`next_human_action`；无法确认时为 `unknown` 或 `needs_human_review`。已观察答案不等于事实真实性，已入库文档也不等于已获批准。

## 5. 工作台与 Agent 设计

### 5.1 信息架构

| 页面/工位 | 主要能力 | 需要可见的状态 |
|---|---|---|
| 项目总览 | 品牌、市场、进行中的采样与任务、最近报告 | 数据截至时间、覆盖范围、失败/未知、权限范围 |
| 品牌事实 | SKU/ASIN 与型号、地区、来源、版本和审批 | 冲突、过期、未审核、声明适用范围 |
| 问句库 | 场景/竞品、候选、审核、冻结及版本差异 | 已冻结不可原位修改、候选来源 |
| 采样运行 | 任务计划、额度、执行进度、人工证据导入 | 未执行、失败、限额、原始证据 |
| 样本与指标 | 原文、来源、抽取结果、人审、指标明细 | 平台和轨道、分子分母、版本、unknown |
| 诊断与任务 | 假设、证据、优先级、责任人、审批/交接 | 已确认/未确认，外部动作权限与回执 |
| 内容审阅 | 事实引用、声明核验、草稿、变更与审批 | 缺依据、冲突、专项审查、禁止发布 |
| 复测与报告 | 可比性检查、对照前后、签发与导出 | 样本覆盖、限制、审阅人、结果版本 |
| 运行与治理 | 数据源、权限、成本、连接、作业失败、审计 | 密钥不显示；告警与恢复状态 |

界面支持空数据、未授权、部分失败、证据不可见、任务等待、平台不可用，不得用 mock 数据伪装真实业务记录。飞书作为发起、状态和导航的候选入口，复杂配置及证据审阅建议放工作台；具体的群与私聊披露、是否启用卡片操作及两端授权待评审。群回复需单独核验受众，不能因发起人有权或链接受保护，就假定群内摘要安全。详见[飞书与工作台交互讨论稿](./2026-11-08-geo-feishu-workbench-discussion.md)。

**示例业务旅程（交互示意，不代表已有数据或系统）：**

1. 运营提出受限业务问题前，应先确认群是否允许展示其问题内容；机器人按服务端身份和项目权限处理，群内是否回应以及可见内容按群受众规则单独评估。缺少可比较样本时，在获准的视图中显示「暂无可判断数据」，不编造结论。
2. 经授权的工作台结果可显示入口、问句版本、采样窗口、覆盖、可判断分母、观察、证据及限制；能否展示原答案或来源还须核对具体用途与留存权限。群消息和通知预览本身也可能暴露信息，链接鉴权不能保护已经在消息中显示的内容。
3. 用户选择一个已观察到的缺口，系统汇集产品事实和引用，生成「观察 / 可能原因假设 / 建议动作 / 需要谁核实」的诊断草稿，交业务人员确认。不能将「未被引用」自动判定为缺少 Schema。
4. 经批准的事实可用于生成页面 FAQ 草稿，涉及健康、安全或报销的声明进入专项审批；任务只能创建内部候选记录，任何 Shopify 或媒体外发均需额外授权。
5. 人工登记实际动作及完成时间，选择同一冻结协议发起或导入复测；报告并列两期样本及失败数，显示变化与可比性，不声称此变化由该动作导致。

**推荐报告结构：** 范围和摘要 → 采集协议/覆盖与失败 → 平台分层指标及 `x/n` → 样本答案与来源 → 品牌事实冲突 → 诊断假设/优先级 → 审批及任务状态 → 可比复测 → 限制、风险、责任人与下一次复查。报告无有效数据时必须显式显示不完整，不生成虚假的总分或 ROI。

### 5.2 Agent 边界与工具

- 由确定性流程管理任务状态、权限、预算、数据访问和报告发布；模型用于受约束的意图理解、辅助解析、证据检索和草稿生成。
- 建议工具：查询项目及问句、查询已授权快照、发起获批准采样、读取经授权事实、生成诊断草稿、创建内部候选任务、查询执行状态。各工具定义输入 schema、输出、超时、错误、可见数据和权限。
- 将外部网页、搜索结果、飞书消息和上传文件视为不可信内容，不能提升权限或成为系统指令；对链接抓取做网络与内容安全控制，限制内网访问、敏感信息泄露及过大附件。
- 先检查证据质量和工具契约，再调整 prompt；模型置信度不是证据，涉及声明冲突时返回待审。
- 每次运行有 `run_id`、执行者/工作区、版本、成本、状态和可追溯工具调用摘要；对外报告不得暴露原始内部提示词、凭证或其他租户资料。

## 6. 飞书长连接与回调专项

### 6.1 接入原则

【B：官方文档】[长连接事件](https://open.feishu.cn/document/server-docs/event-subscription-guide/event-subscription-configure-/request-url-configuration-case?lang=zh-CN) · [接收消息](https://open.feishu.cn/document/server-docs/im-v1/message/events/receive) · [回调与事件](https://open.feishu.cn/document/event-subscription-guide/callback-subscription/callback-overview?lang=zh-CN) · [卡片回调配置](https://open.feishu.cn/document/event-subscription-guide/callback-subscription/step-1-choose-a-subscription-mode/configure-callback-request-address?lang=zh-CN)：

1. 目标为企业自建应用，使用官方 SDK 建立 WebSocket 长连接；服务需具备适当公网出站能力。配置保存时须有在线连接，订阅和权限变更按平台流程发布审核。
2. 单应用最多 50 个连接；多个客户端对事件随机分发而非广播。开发、测试与生产应使用隔离应用/测试企业，避免本地进程与生产抢事件。所给 App ID 是否为独立 GEO 应用及现有权限尚未确认。
3. 订阅 `im.message.receive_v1`，分别覆盖私聊和群 @。建议首期申请 `im:message.p2p_msg:readonly`、`im:message.group_at_msg:readonly`、`im:message:send_as_bot`，实际以目标 API、管理员审批及最新官方文档为准；不申请读取群内全部消息，除非后续另获授权。
4. 长连接完成建连鉴权后，平台描述业务侧无需逐条解密验签；传输加密并不意味着落库、日志和权限可忽略安全。WebSocket 出网策略、断线重连、SDK 行为与回调能力均需环境实测。
5. 消息事件与交互卡片回调分开配置、分开测试。事件可能重推；卡片交互是同步回调，**不应假设平台会补推失败动作**。

### 6.2 消息处理与故障语义

```text
飞书事件 → 长连接 gateway
  → 解析与范围校验 → 事务写入 inbox + 待处理工作
  → 成功返回（目标平台的 3 秒窗口内）
  → worker 领取任务 / 权限再校验 / 预算检查
  → 写入结果和 outbox → 发消息/卡片 → 保存回执或不确定状态
```

- 消息事件按飞书说明使用 `message_id` 做业务去重，通用事件按各事件文档使用 `event_id`/`uuid`，保留相关 ID 作为追踪字段；以租户/应用范围建立唯一约束。不要假设 `event_id` 能替代消息去重。
- inbox 与待处理任务要在同一持久化事务中提交，或使用等价可靠机制；**持久化失败不能伪装成功 ack**。3 秒内未完成时按 SDK 官方语义触发失败/重推，并告警。
- worker 使用有租约的领取、重试上限、死信与人工恢复；同一会话执行顺序和并发策略须明确，跨进程不依赖内存状态。
- outbox 避免本地状态和发信脱节，但远端可能已接收、本地未收到回执：不得宣称天然 exactly-once；使用平台支持的幂等能力或查询回执与人工核对不确定状态，避免盲目重复发信。
- 同一会话隔离按服务端租户、应用、用户、群和项目授权边界执行，群消息不能借用其他用户的私聊上下文；机器人消息过滤以避免循环。
- LLM、网页访问、报告生成和其他长任务不在接收 handler 中执行。用户在任务完成后收到受权限约束的状态卡或回复。

### 6.3 交互卡片与人工操作

- 卡片显示采样进度、证据、错误、诊断或待审批任务；按钮可用于查询详情、请求复测、创建内部候选任务、审批或驳回。哪些按钮可以真正修改状态由角色权限决定，外部写操作默认关闭。
- 卡片 `card.action.trigger` 为同步回调：快速验证服务端用户、工作区、动作、对象权限、有效期与当前状态，可靠持久化操作请求后在平台时限内返回有效结果；耗时工作异步执行。
- 卡片携带不透明短期令牌/动作 ID，不信任客户端自带角色或可篡改参数；回调到来时重新校验授权，按钮重复点击对应稳定业务幂等键。
- 因卡片回调无补推：无法持久化时返回清晰失败和重试入口；如结果不确定，先查询任务状态再允许重试，避免重复审批、派单或外部副作用。

### 6.4 飞书验收矩阵（须先授权测试）

- [ ] 测试应用单聊收信、回复、任务查询通过；正式应用单独验收。
- [ ] 测试群中 @ 正确机器人触发；未 @、其他机器人消息、无权限用户不触发或明确拒绝。
- [ ] 事件重复、并发、延迟、网关重启、数据库暂不可用，均不丢已确认任务、不重复产生业务动作。
- [ ] 测试卡片成功、重复点击、无权限、过期、回调超时和持久化失败，状态及重试提示一致。
- [ ] 检查 3 秒回执窗口、长任务异步处理、错误可观察；具体 p95/p99 和告警阈值在环境基线后确认。
- [ ] 核对权限/发布状态、密钥轮换与访问范围；检查日志和界面中无 secret、无越权原文。

|---|---|---|---|

| 04 验收 | 离线夹具、集成、授权测试环境、人工事实标注和业务 UAT | 不可变测试证据、失败样例、缺陷与整改 | 至少亲眼观察一项检查先失败再修复；跳过不算通过；成功+失败+未执行守恒；P0 缺陷清零或明确 HOLD |
| 05 交付 | 发布说明、环境/权限、操作指南、灰度、回滚、备份恢复、接收人签收 | 交付回执、运行手册、应急方案、成本与额度 | 另一位用户无须开发者在旁解释即可独立完成真实任务；手机/桌面可访问；密钥不落文件；生产接入与真实外发需单独授权 |
| 06 运营 | 技术侧埋点、作业历史、成本、权限审计、事故与 SLA；产品侧观察谁在用、用了几次、在哪一步放弃及反馈 | 运行/成本/事故记录与运营周月报；按授权和隐私边界统计使用用户、任务次数、完成率与放弃步骤 | 做 N 次能核对 N 条记录；故障可定位；刷新不污染指标；可按角色与步骤复核使用和流失，分母及观察窗口清楚；额度与停止条件可查 |
| 07 迭代 | 整理高频问题、人审反馈和真实缺口，形成新需求并复测 | 问题清单、变更记录、回流需求、下一周期计划 | 每项改进有证据、owner、复查日；不自动把未审提问或生成脚本纳入正式 SOP |
| 管理贯穿 | 需求、设计、任务、事故、资产、证据、回执、ADR 各有唯一归档位置 | `R-`、`D-`、`T-`、`INC-`、`ART-`、`E-`、`REC-`、`ADR` | ID 唯一；done 必须指向证据；若采用 Main 检查器须先核验其代码可用性，不能声称当前已运行 |

**Agent 与数据产品两条线**：Agent 交付按上述 7+1；数据管线另按 Main 的采集、存储、打标、指标、分析、呈现、结论、报告 8 层，以及口径、质量、血缘三条横切义务设计。对每层记录输入、输出、失败模式和检查器，真实 0/失败/未到周期不能混淆。Main 的样张是数据产品模板，不自动等于 Agent PRD。

## 8. 里程碑、依赖与资源

### 8.1 可讨论的依赖序列

> 以下清单供后续各节点确定 owner、准入和退出证据；现在全部未执行，不等同已批准启动。

- [ ] M0：完成范围、既有资产与授权核验，登记未决事项。
- [ ] M1：确认需求、首期样本协议、权限和设计，并批准首个子计划。
- [ ] M2：在隔离环境验证一条带真实或获授权导入证据的窄切片。
- [ ] M3：打通六能力的试点闭环，完成负向与故障测试。
- [ ] M4：完成业务 UAT、运行手册、恢复演练与明确的交付签收。
- [ ] M5：依据试点反馈和批准的预算，扩展 SKU、平台、市场及自动化。

| 里程碑 | 工作与可验证结果 | 前置依赖 |
|---|---|---|
| M0 范围和资产核验 | 明确现有 GEO/域名与本项目关系，选定业务 owner、市场、ASIN、入口、预算、App 归属；取得事实/主键字典和数据授权 | 业务及系统 owner 可参与；仅进行获授权的只读调研，不对外写入或变更 |
| M1 需求与设计冻结 | 访谈与需求；样本协议、事实/声明、权限、工作台与飞书契约；Main 复用决策；形成子计划 | M0 与首期素材；冻结的是试点范围而非未来全量 |
| M2 纵向切片 | 在隔离环境完成一次文本 P2P/群 @ → 已授权真实或人工导入样本 → 带证据查询 → 卡片状态/工作台结果 | SDK/网络、测试应用、样本和访问授权 |
| M3 六能力闭环 | 问句冻结 → 采样 → 标注 → 诊断 → 人审草稿/候选任务 → 同协议复测；完成故障和越权测试 | M2、事实 owner、可用采样入口、审核与算力预算 |
| M4 试点交付 | 小范围业务 UAT、验收签字、备份恢复、回滚与可观测、成本/权限审计；生产变更另授权 | M3 验收通过、应用发版审批、生产资源 |
| M5 运营扩展 | 根据真实使用迭代，逐步扩展 SKU/平台/市场与外部交接；经过授权后评估定时化 | 试点业务接受、采样协议和成本可持续 |

M2 是最窄真实闭环，不要求一开始全自动采集；M3 的复测结果需等待真实业务改动和合理观察窗口，不能保证在短开发周期内展示商业提升。

### 8.2 排期处理

PMO 页面 Wave 3 为 **2026-11-24～2026-12-26**，但能力截止日有两版。按配置与问句库、采集探针、解析与指标、诊断洞察、内容生成、复测与报告的顺序，项目卡分别列出 **12-04、12-06、12-11、12-15、12-20、12-26**；2026-11-03 变更留痕分别列出 **11-25、11-25、12-03、12-03、12-09、12-23**。这些仅是 PMO 页面在 2026-11-08 的两组记录，并非本计划承诺。

先核对权威版本、人员可用性、飞书审核、真实数据、采集条款、合规审核与现有底座，再排负责人和关键路径；**当前不提供伪精确日期承诺**。如需按 PMO 窗口推进，建议在窗口前完成 M0/M1 的准备，窗口内优先 M2/M3 试点，但能否达成由依赖核验与团队容量决定。

### 8.3 角色/工作量与预算框架

- 最小角色：产品/业务 owner、GEO/SEO 运营、产品事实 owner、技术负责人、全栈/后端、前端、飞书集成、数据/评测、QA、合规及运营；一人可以承担多个角色，但职责和审核独立性不能消失。PMO 的 P1/P2/P3 三棒可作为分工参考，最终 RACI 由负责人确认。
- 估算公式：`总人日 = 已拆分任务估时之和 + 集成/测试/故障演练 + 跨团队等待与风险缓冲`；并行工期由关键路径而非人日简单相加决定。未核实代码、团队和授权前，不给人数或交付周数承诺。
- 单轮成本框架：`采样调用量 × 单价 + 搜索工具调用费 + token/推理费 + 人工采集与标注时长 + 存储/网络 + 运维`。设置单次、每日、每月上限，超限停止/等待审批。平台价格与条款实施前重新核对，不以过期数字作为预算。
- 定时复测前核实样本量、成本上限、平台条款和业务审批；平台无可靠自动入口时，人工执行也必须获得适用协议和必要许可，不能为了自动化或人工兜底牺牲合规或口径。Perplexity 消费端项目采样当前 HOLD，见[本节点讨论稿](./2026-11-08-geo-sampling-metrics-discussion.md)。

## 9. 测试、交付与安全门禁

### 9.1 测试层次与场景

| 测试 | 必测样例 |
|---|---|
| 数据契约 | 无来源、版本冲突、跨地区 SKU 混淆、原始快照缺失；unknown 不被记作 0 |
| 测量与解析 | 品牌别名歧义、只提及未引用、引用但不支持、非比较问题、列表首位非 Best Overall、无 AI 功能触发、不同版本不可比；重复采样核对新会话、上下文与间隔，未满足协议不得冒称独立观测 |
| 抓取与资格审计 | 以 fixture 验证伪造 UA、身份未验证和已验证日志分离；检查索引、摘要、Search generative AI 控制及缺权时的 unknown；实际日志和平台账号仅在授权取得后验收，不将抓取当成引用 |
| 人工标注评测 | 随机抽样标注说明和分歧仲裁；分别报告准确性、样本量与覆盖；人工审核样本不自动升级为全量金标 |
| 工作流 | 正常、平台失败、超时、重试、限流、任务中断恢复、重复与乱序；任务数守恒 |
| 飞书 | 第 6.4 节全部场景，包括卡片回调与无法确认的远端副作用 |
| 身份/隐私 | 未认证 401、无权限 403、跨群/跨项目隔离、权限撤销、日志脱敏、未授权素材不可见；允许和拒绝访问都产生最小审计 |
| 提示注入 | 网页/文件/群消息要求泄密、越权调用工具、伪造审批或改变报告时均被隔离；不可访问内网和凭证 |
| 内容安全 | 健康/功能/报销声明缺证据、来源过期或冲突时不批准；禁止自动对外发布 |
| 运营恢复 | 模型超额、存储不可用、队列积压、事件重试、备份恢复、异常报告和告警可观测 |
| 人工 UAT | 按角色使用真实授权输入完成试点闭环；记录耗时、失败及是否能独立理解输出 |

**负向验收不可省略**：不能只验证一条 happy path；测试跳过或未经授权的实时步骤应标 `incomplete`，不能计入 passed。设定准确率、延迟、可用率等目标前先建立基线与人工金标，不预填未经验证的数值。

### 9.2 交付证据阶梯

- **L0** 讨论稿/本地资料；本计划当前位于此级。
- **L1** 本地运行 smoke：仅证明该输入在本地环境运行。
- **L2** fixture/dry-run：仅证明受控测试条件，不等于真实外部副作用。
- **L3** 经授权、受保护的公网只读 staging：核对身份、审计及信息泄露。
- **L4** 明确授权的实时副作用：真实目标记录与回执可追溯；具体测试范围需事先批准。
- **生产业务验收**：业务验收、权限/人审策略、备份恢复和正式生产决策完成后才能称生产交付。

任一级有 blocker 即明确 HOLD、数量和责任人，不用「基本可用」掩盖；本次未对任何一项能力做上述运行验收。

### 9.3 审批和内容合规

- 品牌事实 owner 审核型号、配件、地区授权、服务和产品功能；合规团队审核健康、安全、疗效、HSA/FSA 等内容；实际适用法律、资质与证据要求由专业团队判定。[FTC 健康产品广告指引](https://search.ftc.gov/system/files/ftc_gov/pdf/Health-Products-Compliance-Guidance.pdf)
- PMO 机器人台账列出的 GEO `required_gates=["C"]` 及 OpenAPI 的 C/A/X 仅是内部系统描述；对内容、外部发布及实验需要哪些 gate、谁签发以及是否已可用，应与 owner 核实。建议对外发布 fail-closed，不能由模型自行批准。
- 审核高风险声明时记录适用市场、来源、证据质量、有效期、责任人和不允许的延伸推断。缺依据时要求补证据，而不是虚构引用。

## 10. 主要风险和应对

| 风险 | 影响 | 应对/owner 建议 |
|---|---|---|
| PMO 在线状态与本次页面观察不一致 | 错估已有成果/重复建设 | PMO 与站点 owner 确认真实入口、代码、部署、验收与接手关系 |
| 排期/owner 跨页面冲突 | 承诺不可执行 | 由 PMO 指定权威版本，保留变更记录 |
| BrandOS 事实与 `ai_answer_snapshot_id` 未验证 | 事实生成和数据串联被阻塞 | 数据 owner 提供样例、权限、主键和变更契约；缺失则先小规模人工审核 |
| 平台禁止/限制自动采集或目标地区不可用 | 探针失败/合规风险 | 合规核对条款；API 代理、人工采样与不可用状态分别登记；不绕过控制 |
| 产品型号/地区事实冲突 | 错误或误导性母婴声明 | 事实版本和适用市场显式化、产品与合规审核、冲突阻断 |
| AI 入口不是「20 问/ASIN」通用问法 | 带品牌或 ASIN 的查询可能污染无品牌购买发现样本 | 按问题意图区分无品牌发现、品牌比较和型号核查；ASIN 可仅用于内部关联，只有适用时才出现在问题中 |
| 样本太小或口径改变 | 错误宣称效果/ROI | 冻结协议、分层标记、公开分母及失败、人工核查、避免因果宣称 |
| 飞书测试和生产共用应用 | 随机分流、消息丢失 | 独立应用/企业隔离；共享持久化与故障演练 |
| 卡片不补推或回复状态不确定 | 重复派单或丢动作 | 同步持久化、幂等键、状态查询、失败提示与人工恢复 |
| 把工作流素材当已验证系统 | 延期或交付假绿 | 清理 prompt/zip，重建测试和版本；不运行未知脚本 |
| 隐私与跨群数据泄漏 | 客户信息/内部策略泄露 | 服务端 principal、项目/群 ACL、加密、最小化和保留期、拒绝审计 |
| Prompt injection/不可信页面 | 越权、泄露、发布误信息 | 工具权限隔离、内容隔离、出网控制、人工审批、攻击样本测试 |
| 探针/模型/人审成本失控 | 预算被耗尽 | 预算、配额、取消、成本账本与人工审核吞吐上限 |

## 11. 节点讨论与待决事项

建议后续按照「业务目标与 MVP → 采样和指标 → 事实/内容治理 → 飞书与工作台 → 技术/复用 → 验收/排期」逐节点讨论，每一轮输出经过 owner 批准的决定记录和可执行子规格。

### 第一轮已同意的讨论基线与待落实事项

1. **首期边界**：美国英语、吸奶器、Perplexity 消费端优先、候选 3 个 ASIN；人工观察与导入仅在充分授权下考虑，目前因适用许可待审而 HOLD；具体 ASIN、问题数、预算及真实入口可用性尚待核定。
2. **项目归属与可复用资产**：先核验，再决定承接、扩展或新建；需要确认现有 GEO 真实入口与代码，以及 Main gateway、BrandOS 和主键字典的只读评估条件。
3. **业务结果与验收人**：试点帮助相关团队核查提及、引用和型号事实并形成候选任务；问句、事实、健康/报销声明、诊断与 UAT 的责任人及 Best Overall 定义仍待确认。
4. **交付边界**：首期先生成内部候选任务，不默认真实跨系统派单；飞书应用归属、测试应用和管理员、采样/模型预算、权威排期及后续写入审批链尚待核验。

### 其他待决问题

- 315 SKU × 16 类文件的可用范围、样本、版本、知识来源和业务准确性；可否只读接入，历史型号如何处理。
- 哪些问句为品牌发现，哪些属于不适用 Best Overall 的事实核查；竞品和品牌别名如何批准。
- 平台数据保留条款、真实消费者端测试环境、区域与账户可用性；答案截图/文本使用权限。
- 工作台 SSO/身份系统、运行基础设施、监控、密钥管理、预算和业务连续性要求。
- 每类外部来源、用户提问及日志的敏感级别、保留期、删除机制与数据跨境要求。
- Stage 3 的「三道门禁」与返工率分母、Stage 4 稳定性窗口，以及 C/A/X 具体适用范围和责任人。
