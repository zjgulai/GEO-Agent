| 交付物 | 至少包含 | 验收方式 | 当前状态 |

| 权限与角色清单 | 角色、可见数据、可执行动作、审批人 | 与系统实际权限逐项核对 | 未确定 |

| 故障与恢复方案 | 备份、恢复演练、事故分级、通知路径 | 实际演练并留记录 | 未设计 |
| 成本与额度 | 调用、存储、人工工时口径与上限 | 与预算 owner 核对 | 预算未批 |
| 交付签收记录 | 交付范围、验收结论、遗留项 | 业务 owner 签字 | 未发生 |

## 2. 运营指标口径

| 指标 | 建议定义 | 不能说明什么 |
|---|---|---|
| 使用用户数 | 观察窗口内实际使用的工作区用户数，去重 | 不代表业务价值或覆盖全部目标用户 |
| 任务次数 | 发起、完成、失败、放弃分别计数，含分母 | 次数增长不等于 GEO 表现改善 |
| 放弃步骤 | 用户在哪个环节停止，按环节统计 | 不能推断停止原因，需结合反馈 |
| 处理时延 | 从发起到可见结果的耗时分布，注明环境 | 本地或演示环境数据不代表生产 |
| 成本 | 模型调用、存储、人工工时分别记录 | 未批预算前不给成本结论 |
| 权限审计 | 允许、拒绝、撤销事件各计数 | 只记成功等于越权不可见 |
| 数据质量 | 失败、无效、未执行、unknown 的占比 | 与业务效果是不同维度 |

所有指标须写清分母、观察窗口、环境与版本；刷新页面、重复点击和测试账号应排除或单列。运营指标不替代复测报告，也不用于宣称排名、引用或订单提升。

## 3. 运营边界

- 未获授权前不接入真实用户流量、不采集真实使用数据、不做生产监控。
- 日志与审计最小化：记录事件类型、结果与必要标识，不写入敏感正文或凭证。
- 允许与拒绝都应有审计；权限撤销后不再展示缓存结果。
- 事故分级、响应时限与通知对象待业务与运维 owner 确定；本稿不承诺 SLA。
- 成本上限、停止条件与超额处理须在预算批准后写入运行手册。

## 4. 迭代闭环

1. **输入**：人审反馈、高频问题、诊断缺口、事故记录、复测结果、用户放弃环节。
2. **筛选**：经审阅的问题才进入需求池；未审提问、模型建议和临时脚本不自动进入正式 SOP。
3. **记录**：每个改进项写明问题、证据、影响范围、owner、复查日期。
4. **验证**：改动后按验收单元复验，必要时按可比协议复测；不自动修改模板或正式流程。
5. **回看**：定期复核已关闭项是否复现，保留历史版本。

## 5. 交付前检查（对应 M4，不排日期）

- 另一位用户无须开发者在旁解释即可独立完成任务。
- 桌面与移动端可访问（如适用），关键路径可用。
- 凭证不落文件、不出现在日志或界面。
- 备份与恢复经过实际演练。
- 权限拒绝、撤销与故障路径有记录。
- 生产接入、真实外发与定时任务分别获得授权。
