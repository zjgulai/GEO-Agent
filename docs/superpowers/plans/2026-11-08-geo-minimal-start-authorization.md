## 2. AUTH-01：飞书测试应用

### 2.1 需要管理员在开放平台完成的操作

1. 在**测试企业**创建企业自建应用（或指定一个已隔离的测试应用），开启机器人能力。
2. 事件订阅选择长连接方式，订阅 `im.message.receive_v1`（接收消息 v2.0）；不要同时订阅同一事件的 v1.0 与 v2.0。
3. 按目标 API 申请最小权限，建议起点为：`im:message.p2p_msg:readonly`、`im:message.group_at_msg:readonly`、`im:message:send_as_bot`；不申请读取群内全部消息的敏感权限。实际 scope 与审批要求以管理员看到的最新官方文档为准。
4. 发布测试版本，将测试机器人加入指定的测试群。
5. 确认测试与生产使用不同应用/企业，避免同一应用多客户端随机争抢事件。

### 2.2 需要回传的信息

- 测试 App ID；
- 测试企业/群标识（用于配置验证范围）；
- 已批准 scope 清单与管理员确认结论。

**App Secret 不要发在对话、文档或日志中。** 正式接入前按既有建议轮换历史凭证，并由密钥管理注入；本阶段不索取、不记录任何 secret。

### 2.3 本阶段我会做与不做

- 会：在收到 App ID 后整理配置核对清单、权限与事件映射表，准备隔离环境下的结构验证方案。
- 不会：代为操作开放平台控制台、申请权限、发布版本、连接生产应用或发送任何真实消息。

## 3. AUTH-02：PMO 资产只读核验

### 3.1 建议的核对对象

| 对象 | 只读目的 | 输出位置 |
|---|---|---|
| PMO GEO 项目页与能力清单 | 核对首期范围、能力链与责任口径 | 工作包 T2/T6 |
| 315 SKU × 16 类事实文件的元数据 | 确认定义、粒度、版本、owner 与可访问范围 | 工作包 T3 |
| BrandOS 页面所称 315/62/68 等数字 | 核对口径与数据截至时间，不与 PMO 数字直接等同 | 工作包 T3 |
| `ai_answer_snapshot_id` 等主键契约 | 确认定义、粒度、签发方与权限 | 工作包 T5 |

### 3.2 边界

- 只读；不复制、不导出、不送模型、不写入原系统。
- 未获数据 owner 明确的范围时，只整理**公开页面层**的陈述，并标注读取时间与「待 owner 核验」。
- 无法访问的资产记为 unknown，不推断其不存在。
- 本阶段产出是纸面盘点与缺口清单，不是资产验收或事实批准。
